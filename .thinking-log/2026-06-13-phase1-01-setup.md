## 思考：如何讓 localhost:3000 在 Phase 1 就能看到效果？

使用者要求「我要能在 local 看到前端效果才算」。但專案策略是 **Frontend First**——後端 REST API 屬於 Phase 2，現在還沒實作。

**問題：** 前端 Login / Users / Profile 都需要呼叫 `/api/v1/*`，但這些端點還不存在。

**決策（ADR-Phase1-01）：** Phase 1 建立 **Mock API 層**。
- 用 Next.js Route Handlers（`src/app/api/v1/**/route.ts`）回傳寫死的 mock 資料。
- 前端所有 hooks / Server Actions 照常呼叫 `/api/v1/*`，但 Phase 1 打到 mock。
- 這樣 `localhost:3000` 完全自包含、可獨立運行、Playwright 可實際點擊驗證。
- Phase 3 整合時，把 `next.config.ts` rewrite 指向真實 Spring Boot，移除 mock route handlers。

**為何不直接接舊後端（Ext Direct）？**
- 舊後端走 `/router` Ext Direct RPC 協議，與新前端期望的 REST JSON 不相容。
- 為了 Phase 1 能獨立驗收，mock 是最低風險、最快見效的路徑。

## Mock 資料設計

需要的 mock 端點（對應 design.md §3.3）：
- `GET /api/v1/auth/me` → 回傳 admin 使用者
- `POST /api/v1/auth/login` → 回 `{ mfaRequired: false }`，set mock session cookie
- `POST /api/v1/auth/logout`
- `GET /api/v1/navigation` → ADMIN 選單樹
- `GET /api/v1/users?page=&size=&q=` → 分頁 mock 使用者清單（~30 筆）
- `PUT/DELETE /api/v1/users/{id}` → 回成功
- `GET /api/v1/authorities` → `["ADMIN","USER"]`
- `GET/PUT /api/v1/me/settings`、`/api/v1/me/devices` 等

mock 資料放 `src/lib/mock/data.ts`，route handlers 引用，方便 Phase 3 整批移除。
